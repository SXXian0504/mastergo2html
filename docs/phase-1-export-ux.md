# 阶段 1 导出性能与体验优化实施记录

## 1. 本阶段目标

阶段 1 目标是解决“大图导出慢、用户以为卡住”的体验问题，让插件在进入 AI 工作流前成为稳定、可诊断的数据入口。

本次实现重点：

- 默认快路径仍为仅导出结构和资源引用。
- 用户可以明确选择导出模式。
- 导出过程显示失败数和风险提示。
- 导出结果包含耗时、预估 ZIP 大小、失败资源摘要。
- ZIP 中新增 `export-report.json`，保存可追溯的性能和错误信息。

真实使用中已经发现，大图片导出仍然可能很慢。因此阶段 1 的后续策略不是继续强化“全量导出”，而是把资源导出改成按需补导。完整策略见 `docs/asset-export-strategy.md`。

同时也已发现当前图片切片存在不准确和遗漏。原因是当前切片任务来自图片资源引用，并不等于完整页面视觉节点集合。后续切片应改为由 `asset-export-plan.json` 指定目标节点、边界策略和优先级。

最新实测显示，`结构 + 原图` 模式导出 1 个根节点、265 个总节点、18 个原图资源时，最终预估 ZIP 只有 10.1 MB，但总耗时达到 641.4 s，其中主要卡在一张约 9 MB 的图片上。这说明插件内原图读取耗时不可控，当前 8000 ms timeout 只能视为 best-effort，不能作为可靠中断保障。

## 2. 已完成改造

### 2.1 导出模式

UI 从两个 checkbox 调整为四种明确模式：

- `仅结构`：导出 `raw.json`、`asset-manifest.json`、`export-report.json`，跳过图片文件。
- `结构 + 原图（不推荐）`：额外导出 `assets/original/*`；单张大图可能耗时数分钟。
- `结构 + 图片节点切片`：额外导出 `assets/rendered/*`，但只覆盖 `imageRef` 来源节点，可能不准或遗漏。
- `全部导出`：同时导出原图和图片节点切片；最慢，且切片仍不保证完整。

默认模式是 `仅结构`，对应阶段 1 的性能优先策略。

### 2.2 进度反馈

`ExportProgress` 新增：

- `failed`：当前累计失败数。
- `warning`：当前阶段风险提示。

UI 在导出中展示：

- 当前阶段。
- 当前进度。
- 当前处理节点或资源名称。
- 失败数量。
- 大资源模式提示。

### 2.3 失败不中断

当前行为：

- 单个原图读取失败不会中断整体导出。
- 单个渲染切片失败不会中断整体导出。
- 失败资源写入 `asset-manifest.json` 和 `export-report.json`。

已存在超时：

- 原图单资源超时：8000 ms，但在大图场景下可能无法可靠中断 MasterGo 原生资源读取。
- 渲染切片单资源超时：12000 ms。

### 2.4 导出报告

ZIP 新增：

```text
export-report.json
```

报告内容：

- 导出选项。
- 节点数、图片数、原图导出数、跳过数、失败数。
- 渲染切片成功数和失败数。
- 文件数量。
- ZIP 预估大小。
- 总耗时。
- 阶段耗时。
- 风险提示。
- 失败资源列表。
- 后续补导建议。

### 2.5 结果页摘要

导出完成后 UI 展示：

- 根节点数。
- 总节点数。
- 原图资源数。
- 渲染切片数。
- 失败资源数。
- 预估 ZIP 大小。
- 总耗时。
- 提示和失败资源摘要。

## 7. 对后续阶段的影响

阶段 2 schema 设计可以直接消费：

- `export-report.json` 中的失败资源列表。
- `asset-manifest.json` 中的 `status`、`error`、`copiedPath`。
- 导出选项与耗时信息。

后续建议：

- 增加按 `assetId` 补导的 UI 或消息类型。
- 在 `asset-manifest.json` 中增加资源体积字段。
- 在导出前根据图片数量和节点尺寸给出更准确的耗时风险等级。
- 如果支持当前页面所有 Frame 一键导出，默认只导出结构和资源引用，静态资源由 `asset-export-plan.json` 驱动补导。
- 将切片从首轮自动批量导出改为按 `nodeId` 的计划型补导。
- 原图文件获取优先移到本地 workflow，通过 `imageRef` 下载、Content-Length 检查、流式写入和可中断超时控制实现。
