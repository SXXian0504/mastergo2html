# MasterGo2Code · Codex Skill 产品发布会方案

> 最终方向：只展示 Codex Skill 路径  
> 发布日期：2026 年 8 月 6 日  
> 正式内容：建议 22–24 分钟  
> 问答缓冲：5–6 分钟  
> 总时长：严格控制在 30 分钟以内

## 1. 唯一核心承诺

整场发布会只讲清楚一件事：

> **只需要一句话，Codex 就能把 MasterGo 中选中的多个页面，转换成一个可运行、可继续开发的 React 项目。**

不要在主线中介绍：

- MasterGo 插件入口；
- 本地服务如何部署；
- MCP Server 端口；
- HTML 阶段的全部中间文件；
- 每一个 Agent 或脚本的职责；
- 两条不同使用路径。

HTML 是实现过程，不是发布会最终结果。面向设计师时，最终结果应当是：

> **设计稿变成了一个真正可以运行和继续开发的产品工程。**

## 5. Apple Keynote 风格原则

Apple 风格不是“黑色背景 + 渐变”，而是一种信息控制方式。

### 原则一：一屏一个结论

每一页只允许观众记住一句话。不要使用传统的：

```text
标题
- 功能一
- 功能二
- 功能三
- 功能四
```

改为连续四页：

```text
复杂素材，完整保留。

多个页面，一个工程。

真实路由，自动连接。

可运行，也可继续开发。
```

### 原则二：标题直接说结论

不要写：

> 现状分析

改成：

> 一句话的需求，常常变成几十行 Prompt。

不要写：

> 产品优势

改成：

> 用户只需要说明目标。

### 原则三：产品画面是主要证据

- 产品截图占画面 70%–90%；
- 文字只负责告诉观众应该看什么；
- 不用装饰性插画填空；
- 不长时间展示代码和终端；
- 不使用复杂数据图表证明视觉效果。

### 原则四：逐层揭示

一页不要一次展示所有内容。

例如先显示：

> 问题不是模型不会写代码。

停顿后进入下一页：

> 而是正确的方法没有被固化。

### 原则五：克制

- 不使用玻璃拟态大杂烩；
- 不使用持续旋转和漂浮；
- 不使用多个强调色；
- 不使用密集卡片网格；
- 不在每一页都做 Morph；
- 不模仿 Apple Logo 或具体产品造型。

## 6. 推荐的 17 页 Slide

虽然有 17 页，但多数页面只有一句话或一个产品画面。Apple 发布会式演示的节奏来自快速、清晰的页面切换，而不是把所有信息塞进少数页面。

### 01｜Opening Statement

**画面：** 纯黑背景，居中大字。

> 设计师不该为了生成页面，  
> 先学会写 Prompt。

字号 72–88 pt。无 Logo，无姓名，无副标题。

讲述：

> 今天，AI 已经很会写代码了。但当设计师真正尝试把设计稿变成页面时，第一步往往不是设计，也不是开发，而是学习怎么向 AI 解释自己的设计。

动效：只有淡入。

---

### 02｜The Friction

**画面：** 暖白背景。一句超大标题，右下角出现一段被模糊处理的长 Prompt。

> 一句话的需求，  
> 常常变成几十行解释。

讲述：

> 页面结构、素材、字体、响应式、交互、多页面关系，每一项都需要重新告诉 Agent。如果遗漏一项，结果就可能发生偏差。

---

### 03｜The Failure

**画面：** 黑色背景，居中放大错误的页尾 Logo 黑框。

> 代码生成了。  
> 设计却丢失了。

不要在这一页放三方对比，只放错误结果，制造冲突。

---

### 04｜The Evidence

**画面：** 三列全屏视觉对比。

```text
Design        Default Result        MasterGo2Code
```

只聚焦蒙版 Logo 或最明显的布局差异。列标题非常小，画面本身最大。

讲述：

> 这不是审美差异，而是设计信息有没有被正确读取。复杂蒙版、素材组合和布局关系，无法只靠一句通用生成指令稳定恢复。

---

### 05｜Reframe 01

**画面：** 纯黑背景。

> 问题不是模型不会写代码。

说完后停顿一秒，切下一页。

---

### 06｜Reframe 02

**画面：** 纯黑背景，强调词使用产品蓝。

> 而是正确的方法，  
> 没有被固化。

讲述：

> 每一次任务都重新写 Prompt，相当于每一次都重新发明工作流。真正需要被产品化的，是设计稿转代码的方法、步骤和验收规则。

---

### 07｜Product Reveal

**画面：** 黑色背景，产品名居中。

# MasterGo2Code

下方小字：

> A Codex Skill for Design-to-React

讲述：

> 所以我把完整的设计稿转换方法封装成了一个 Codex Skill。它记住应该怎样读取设计、怎样逐页生成、怎样验证结果，以及怎样把多个页面变成一个工程。

动效：产品名使用一次 0.8 秒左右的蒙版 Reveal。全场最明显的一次动画只放在这里。

---

### 08｜The Prompt

**画面：** 暖白背景，画面中央只有真实指令。

> “将当前选中的 MasterGo 页面  
> 转换成 React 项目。”

下方小字：

> That’s it.

讲述：

> 用户不再负责设计工作流。用户只需要说明目标，Skill 负责执行专业过程。

---

### 09｜How It Works

**画面：** 五个横向阶段，图形尽量抽象、简单。

```text
Read Design
     →
Build Pages
     →
Verify Visually
     →
Create React App
     →
Validate Project
```

中文可以放在阶段下方的小字中：

```text
读取设计 → 逐页生成 → 视觉验证 → React 合并 → 工程检查
```

不要展开十几个内部步骤。

### 10｜Demo Chapter Card

**画面：** 纯黑背景。

> From frames  
> to a working product.

下方中文小字：

> 从多个设计页面，到一个可运行项目。

停顿后播放视频。

### 11｜Edited Demo Video

**形式：** 全屏播放 4 分 30 秒～5 分钟的剪辑视频。

视频中完成：

1. 展示 MasterGo 中已选中的多个 Frame；
2. 在 Codex 中输入一句任务；
3. Skill 被识别和读取；
4. 设计页面被逐个转换为 HTML；
5. 每页进行截图验证；
6. 多个页面进入 React / Next.js 项目；
7. 展示首页、列表、详情之间的跳转；
8. 展示一个响应式结果；
9. 展示 typecheck、build 和视觉验证结果；
10. 最后以多个路由并列画面定格。

视频播放前说：

> 接下来请重点看两件事：我输入了多少信息，以及 Skill 自动接管了多少步骤。

播放中尽量不持续讲话。让视频字幕承担阶段说明。

---

### 12｜Proof 01

**画面：** 蒙版 Logo 设计稿和最终结果，大面积并排。

> 复杂素材，完整保留。

讲述：

> Skill 不只把页面当作一张截图，而是使用设计节点、素材映射和渲染证据恢复复杂资源。

---

### 13｜Proof 02

**画面：** 三张完整页面垂直或水平排列，最终收拢到浏览器窗口。

> 多个页面，一个工程。

讲述：

> 每个 Frame 先独立生成和验证，确认页面结果后，再进入工程合并。这样不会因为组件复用，提前破坏某一页的视觉结果。

---

### 14｜Proof 03

**画面：** 浏览器路由切换为主，右下角只保留三个绿色状态。

> 可运行，也可继续开发。

小字状态：

```text
TypeScript Passed
Production Build Passed
Visual Regression Recorded
```

不要展示完整终端日志。

---

### 15｜Ownership

**画面：** 黑色背景，中心是一条完整闭环。

> One workflow.  
> Built end-to-end.

下方使用非常克制的小字：

```text
Design extraction · AI workflow · HTML generation
Visual validation · React migration · Engineering checks
```

讲述：

> 这个 Skill 以及背后的完整链路由我独立开发。真正困难的不是让模型输出代码，而是让设计采集、素材处理、分阶段生成、视觉验证和工程迁移形成一个可重复闭环。

这一页承担最终考核中的个人贡献表达，不要再增加传统“我的工作内容”列表。

---

### 16｜Boundary

**画面：** 暖白背景。

> 第一版，不是终点。

下方只保留三行：

```text
复杂业务逻辑仍需开发接入
特殊视觉效果仍需继续校正
真实团队规范仍需工程适配
```

讲述：

> 它不替代前端完成整个产品，而是把设计交付推进到一个可运行、可验证、可继续开发的起点。

---

### 17｜Closing

**画面：** 纯黑背景，产品名和主张。

# MasterGo2Code

> 一句话，从设计稿到 React 项目。

结尾话术：

> 我做的不是另一个需要设计师维护的大 Prompt。我希望把设计稿转代码的专业方法交给 Skill，让设计师只需要说明目标，让前端从一个可运行、可验证、可继续开发的项目开始。MasterGo2Code，一句话，从设计稿到 React 项目。

说完后停留两秒，再口头说谢谢。

| 01:45–02:15 | 每页截图验证 | Verify against the design |
| 02:15–02:45 | 多个页面合并为 React 项目 | Merge into one React app |

- 等待模型输出的完整过程；
- 大量终端字符滚动；
- 文件夹中逐个查找文件；
- 鼠标寻找按钮的过程；
- 失败操作和重新输入；
- 重复展示三个页面的相同步骤；
- 观众看不懂的内部 JSON；
- 没有解释价值的代码特写。

### 视频中必须保留

- 用户真实输入的一句话；
- Skill 被调用的明确证据；
- 多个 Frame 被逐页处理；
- 视觉验证阶段；
- React 路由切换；
- 蒙版 Logo Hero Case；
- typecheck / build 结果；
- 实际原始耗时标注。

## 8. 视觉系统

### 画布

- 16:9；
- 1920 × 1080；
- 安全边距：左右至少 120 px，上下至少 90 px；
- 所有视频也按同一尺寸剪辑。

### 色彩

只使用四种颜色：

```text
Black       #000000
Off White   #F5F5F7
Text Black  #1D1D1F
Product Blue #5B7CFF
```

成功状态可以少量使用绿色，但只用于验证结果。

不要直接复刻 Apple 的产品蓝、彩虹渐变或玻璃材质。高级感来自信息密度与排版，不来自模仿具体品牌资产。

### 字体

Mac/Keynote：

- 中文：PingFang SC；
- 英文与数字：SF Pro Display / SF Pro Text；
- 代码：SF Mono。

跨平台 PowerPoint：

- 中文：HarmonyOS Sans SC 或思源黑体；
- 英文：Inter；
- 代码：JetBrains Mono。

### 字号

```text
Statement 标题：72–96 pt
普通标题：56–72 pt
副标题：28–34 pt
辅助文字：20–24 pt
超大数字：140–220 pt
```

不要为了塞文字把字号降到 18 pt 以下。

---

## 9. 动效系统

全套只使用三种：

1. **Dissolve / Fade**：普通页面切换；
2. **Magic Move / Morph**：Frame 进入网页、多个页面收拢为工程；
3. **Mask Reveal**：产品名首次登场。

时长：

```text
Fade：0.25–0.4 秒
Magic Move：0.5–0.7 秒
Product Reveal：0.8 秒左右
```

不要使用：

- 弹跳；
- 旋转进入；
- 从四周飞入；
- 持续漂浮；
- 每一页都 Morph；
- 背景粒子；
- 无意义光效。

章节页可以直接硬切黑屏，停顿半秒。克制的停顿本身就是节奏。

## 11. 最后删减检查

每一页都问：

> 如果删掉这一页，观众是否仍然能理解产品？

如果答案是“可以”，就删掉。

最终只保留能够完成以下四件事的页面：

1. 让观众感受到现有问题；
2. 让观众理解为什么需要 Skill；
3. 证明产品真的能够完成任务；
4. 让评委看见你的独立贡献和产品判断。
