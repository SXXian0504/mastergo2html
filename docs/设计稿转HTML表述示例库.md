# 设计稿转 HTML · 表述示例库（AI / Codex 协作用）

> 目标：一套代码兼顾 PC 与移动端，先 PC 后移动，自适应优先，尽量不用绝对定位。
> 核心思路：**描述"关系、约束、规则"，而不是"坐标、写死的像素"。** 把不变的规则交给 AI，让它自己选 flex / grid / 相对单位来实现。

---

## 三条铁律（开头先对齐认知）

1. **说关系，不说数值。** 元素位置尽量用"与谁对齐、离谁多远、填满谁的剩余空间"来描述，而不是"距顶部 120px"。
2. **说规则，不说一次性状态。** 用"永远 / 始终 / 随…变化"锁定规则，让它在任意窗口尺寸下都成立。
3. **绝对定位是最后手段。** 只有"浮层、吸附、蒙层"这类脱离文档流的场景才用；能用 flex / grid 排的一律不用 absolute。

---

## 万能句式模板（填空即可用）

- `A 与 B 的间距 = [某个已知尺寸，如 A 的高度 / 统一间距变量]`
- `[元素] 填满 [容器] 的剩余空间，其余元素尺寸不变`
- `[元素] 在 [参照物 / 视框] 内始终 [水平居中 / 靠右 / 吸顶]，缩放时保持不变`
- `[一组元素] 一行放不下时 [自动换行 / 局部滚动 / 折叠]，不允许 [撑破布局 / 横向滚动]`
- `[元素] 尺寸由 [内容 / 比例] 决定，不写死宽高`
- `[断点] 以下，从 [PC 布局] 变为 [移动布局：具体怎么变]`

---

## 一、间距与对齐关系

原则：间距用"相对某个已知量"来锚定，形成统一节奏；对齐说清楚基于哪条线。

- 主标题与副标题的上下间距 = 主标题的行高。
- 卡片之间的横向和纵向间距始终相等，由同一个间距变量控制。
- 表单每一行的上下间距保持一致，行与行等距。
- 图标与相邻文字始终**垂直中线对齐**，字号变化时不错位。
- 同一组内元素间距紧凑，组与组之间的间距是组内间距的 2 倍，用间距层级拉开区分。
- ❌ "标题距离顶部 40px" → ✅ "标题与上方容器边缘的留白 = 标题字号高度"。

---

## 二、尺寸与比例

原则：能自适应就不写死；写死的只留"固定项"，其余用填充、比例、约束描述。

- 左侧导航固定 240px，右侧内容区填满剩余空间，窗口缩放时只有内容区变化。
- 三个统计卡片始终等宽平分一行（各占 1/3），卡片间距不计入等分。
- 地图缩略图始终保持 16:9，宽度自适应、高度按比例计算。
- 按钮宽度由文字内容撑开，左右内边距固定；不写死按钮宽度，以适配多语言变长。
- 内容区最小宽度 1000px，低于此值出现横向滚动，而不是压缩内部元素。
- ❌ "卡片宽度 380px" → ✅ "卡片在容器内等宽平分，随容器变化"。

---

## 三、布局结构与流式排布（避免绝对定位的核心）

原则：横向/纵向的排列关系用 flex / grid 描述，让元素待在文档流里。

- 顶部工具栏横向排列：标题靠左、操作按钮靠右，中间自动留白撑开（两端对齐）。
- 标签 / chip 横向排列，一行放不下时自动换行到下一行，不允许横向滚动。
- 卡片网格每列最小 280px，容器变宽自动加列、变窄自动减列。
- 页面纵向堆叠：筛选区在上（高度由内容决定），数据表格在下（填满剩余高度）。
- 卡片右上角的关闭按钮，用 flex 靠右对齐实现，**不要**用 absolute 钉到角落。
- ❌ "把删除按钮绝对定位到右上角" → ✅ "标题行用两端对齐，删除按钮作为该行最右元素"。

---

## 四、定位与吸附（确实需要脱离文档流时）

原则：即使要定位，也说"锚定谁、约束在哪"，不给死坐标；并且始终保证在视框内可见。

- 下拉面板锚定在触发按钮正下方、左边缘对齐，随按钮位置移动；**不固定屏幕坐标**。
- 弹层展开时若下方空间不足，自动翻转到按钮上方，**始终完整显示在视框内不被裁切**。
- 表格表头向下滚动时吸附在容器顶部（sticky），不脱离文档流。
- 对话框在视框内水平垂直居中，视框缩放时始终居中（用 flex 居中，不用负 margin 绝对定位）。
- 浮层永远盖在页面内容之上，但不遮挡全局顶部导航，层级用统一的 z-index 变量管理。

---

## 五、溢出与滚动

原则：任何"内容可能超出"的地方都要预先说明溢出行为，防止撑破或裁切。

- 单行文本超出容器宽度时省略号截断，悬停显示完整内容（tooltip），不撑破布局。
- 描述文字最多显示两行，超出省略。
- 表格区域内部滚动，表头与分页固定不动，整页不出现滚动条。
- 长列表在容器内滚动，容器高度 = 视框高度 − 顶部/底部固定区，内容再多也不撑高整页。
- ❌ "列表很长时页面往下延伸" → ✅ "列表在固定高度容器内局部滚动，页面整体不滚动"。

---

## 六、响应式断点与 PC → 移动端适配

原则：先写 PC，移动端只描述"在 PC 基础上改什么"（说差量，不重描一遍）；靠容器宽度 / 媒体查询切换，绝不写两套 DOM。

- 断点声明：以 1440px、768px 为界；≥1440 宽屏、768–1440 标准 PC、<768 移动端。
- 移动端在 PC 基础上做以下调整：左右两栏改为上下堆叠，左侧导航收起为顶部抽屉 / 底部 tab。
- 卡片由一行三个变为一行一个纵向堆叠；字号和间距用相对单位随之调整，**不是整体等比缩小**。
- PC 端并排显示的次要信息，移动端收进"更多"或折叠展开，而不是横向压缩硬挤。
- 移动端可点击区域最小 44×44px，按钮和列表项加大点击热区。
- ❌ "移动端把整个页面缩小到手机宽度" → ✅ "移动端元素重排堆叠，字号/间距按相对单位调整"。

---

## 七、状态与动态内容（容易漏，但最影响稳定性）

原则：用"最长、最短、为空、加载中"四种极端内容去描述，保证布局在任意数据下都不跳动。

- 统计数字为空时显示占位符"—"，不留空白导致高度跳动；数字位数变化时卡片高度保持稳定。
- 数据加载时用骨架屏占位，尺寸与真实内容一致，避免加载完成后布局跳动。
- 用最长可能内容测试列宽：文案最长和最短时布局都不破坏。
- 文案变长（英文 / 多语言）时按钮和标签自动加宽或换行，不裁切、不溢出。

# 第二部分 · 素材与文件交付（MasterGo / SVG / PNG）

> 第一部分解决"怎么说"，这一部分解决"给什么、怎么给"。设计文件本身搭得好，AI 转码就成功了一半。

---

## 八、MasterGo 文件怎么搭，才好转代码

- **用「自动布局」搭主结构。** 自动布局天然对应 flex，是"避免绝对定位"的源头——整页、卡片、行、工具栏尽量都套自动布局，而不是自由拖摆。
- **用「约束」表达缩放意图。** 元素设成"左右拉伸 / 固定右侧 / 水平居中"等，让 AI 能读出它在窗口变化时该怎么动。
- **图层命名语义化。** 用 header / stat-card / filter-bar 这类有意义的名字，别留"矩形 12 副本 3"——AI 和开发都靠命名理解结构。
- ⚠️ **不要直接复制开发模式生成的 CSS。** MasterGo（及同类工具）自动生成的代码大量使用 `position:absolute` + 写死宽高，与"自适应优先"完全相反。开发模式**只用来读量值**（间距、字号、颜色、圆角），拿到数值后用第一部分的话术重新描述关系，再交给 Codex。
- **效果用参数交付，不用切图。** 阴影、圆角、渐变、描边给出具体数值（如 `0 4px 12px rgba(...)`），让 AI 用 CSS 实现，不要导出成图片——图片不能自适应、不能改色。

---

## 九、SVG 使用规范

- **图标、简单插画一律用 SVG。** 矢量、可缩放、体积小、可改色，绝不用 PNG 替代。
- **单色图标用 `currentColor` 或颜色变量。** 让图标颜色跟随文字 / 主题（#0068FF）继承，不要写死 `fill`，否则 hover 变色、换肤都改不动。
- **保留 `viewBox`、去掉固定宽高。** 让 SVG 尺寸由外部容器 / CSS 控制，随布局缩放。
- **导出后清理压缩。** MasterGo 导出的 SVG 常带冗余分组、clip-path、超长小数、内联样式；过一遍 SVGO 再用，体积和可维护性都更好。
- **该是文字的不要导出成路径。** 用真文字保证可选中、可翻译（多语言）、可读屏；文字转路径会同时毁掉这三点。
- **多色 / 多状态图标，先说清哪部分可变色。** 告诉 AI 哪几段跟随主题、哪几段固定。
- **需要控色或动画的图标内联进 DOM，纯装饰静态图标用 `<img>` 或背景图。** 前者可控，后者省 DOM 体积。

---

## 十、PNG / 位图使用规范

- **只有照片、真实地图瓦片、复杂材质渐变才用 PNG。** 其余能矢量或 CSS 实现的都不切图。
- **按 2 倍图（@2x）导出，按 1 倍尺寸显示。** 保证高分屏清晰；多倍需求用 `srcset` 提供。
- **圆角、阴影、纯色块、简单渐变不切图。** 用 CSS 实现，可自适应、易修改。
- **交付前压缩，保留透明通道。** 控制体积，别让位图拖慢首屏。
- **命名与归类和图层保持一致。** 方便和结构对应映射。

---

## 十一、静态设计稿"传不出"的信息，必须额外文字说明

一张设计图 = **某一个尺寸下、某一个状态**的截面。以下信息图上没有，必须补文字（呼应第一部分）：

- **交互状态**：hover / 按下 / 选中 / 禁用 / 加载 / 空 / 错误——稿子通常只画默认态。
- **响应式变化**：图只是一个断点，PC → 移动怎么变要说明（见第六部分）。
- **数据极端态**：最长文案、空数据、溢出时布局如何应对（见第七部分）。
- **滚动与层级**：哪块区域内部滚动、浮层压在谁之上——图上看不出。
- **动效**：过渡、展开收起的方式——图是静止的。

---

## 交付前自检（一句话版）

> 每个模块问自己四句：**窗口拉大拉小会怎样？内容变长变空会怎样？在手机上会怎样？这里有没有用到 absolute、能不能改成 flex/grid？**

## 打包给 AI / Codex 时，一起交付这五样

1. **结构说明**——用第一部分话术描述元素关系，而非贴工具生成的 CSS。
2. **关键量值**——间距 / 字号 / 颜色 / 圆角，尽量对应到你们的 token（#0068FF、8/12/20px 等）。
3. **素材**——清理过的 SVG + 必要的 @2x PNG，命名语义化。
4. **状态与交互补充**——默认态之外的所有状态说明。
5. **断点与移动端变化**——说清 PC 之外各断点怎么重排。
