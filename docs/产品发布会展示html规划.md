## 入场动效

封面动效只播放一次，不持续漂浮或循环。

### 动效顺序

1. **背景出现**
   - 白色圆点背景淡入；
   - 右侧蓝紫色柔和光晕缓慢扩散；
   - 时长约 0.5 秒。

2. **产品标题出现**
   - 小标题先淡入；
   - `MasterGo2Code` 从下方向上移动约 20px；
   - 副标题稍晚淡入；
   - 时长约 0.6 秒。

3. **插件界面进入**
   - 插件窗口从右侧滑入；
   - 从 `scale(0.96)` 过渡到 `scale(1)`；
   - 时长约 0.5 秒。

4. **Codex 指令进入**
   - Codex 指令截图从右下方向上浮入；
   - 使用 `clip-path` 从左到右揭示；
   - 最后可模拟光标闪烁两次；
   - 时长约 0.4 秒。

5. **最终停留**
   - 所有元素停止运动；
   - 不使用循环漂浮、旋转或持续缩放。

6. **切换到下一页：双向退场**
   - 用户触发下一页后，先锁定当前页的重复操作，避免连续按键造成动效叠加；
   - 将左侧小标题、主标题和副标题包裹为一个整体，沿水平方向向左滑出；
   - 将右侧插件窗口和 Codex 指令包裹为一个整体，保持两者现有的前后叠放关系，同时向右滑出；
   - 左右两组必须在同一时刻启动，形成画面从中间向两侧打开的效果；
   - 左侧文本组使用 `translate3d(-120%, 0, 0)`，右侧产品组使用 `translate3d(115%, 0, 0)`；
   - 两组在前 70% 的时间内以位移为主，最后 30% 再将 `opacity` 从 1 降到 0，避免元素一开始就变淡，保留明确的“滑出”感；
   - 右侧产品组可同时从 `scale(1)` 轻微缩小到 `scale(0.97)`，制造窗口向远处退出的空间感；左侧文字不缩放，保持标题的稳定和力量感；
   - 蓝紫色光晕跟随右侧产品组向右偏移，并比截图晚约 80 毫秒消失，形成轻微拖尾，但不使用实体光带；
   - 圆点背景和白色底色在退场过程中保持静止，避免整页横移产生晕眩；
   - 退场总时长建议为 0.55–0.65 秒，缓动建议使用 `cubic-bezier(0.76, 0, 0.24, 1)`；
   - 左右内容完全离场后再切换页面；下一页可提前约 80–120 毫秒开始淡入，使页面衔接没有纯白停顿；
   - 如果用户返回上一页，使用完全相反的方向播放：左侧文本从左侧进入，右侧产品组从右侧进入。

整组封面入场动效控制在约 2 秒内；切换下一页的退场动效控制在约 0.6 秒内。

## 动效顺序

### 1. 页面进入

- 延续第 1 页的百无常 `blue` 主题背景和圆点系统；

### 2. 设计稿堆叠建立

- 3–4 张 Frame 从后向前依次出现；
- 每张 Frame 使用轻微的位移和透明度变化；
- 最前方 Frame 最后落位并成为视觉焦点；
- MasterGo Logo 和 `DESIGN FRAMES` 辅助标识同步淡入。

### 3. Frame 依次向右移动

- 按从前到后的顺序，将设计稿从左侧堆叠中逐张抽出；
- 每张 Frame 沿水平方向向右移动，经过中间路径后进入右侧浏览器区域；
- 移动过程使用轻微蓝色轨迹或短暂的蓝色线段，不使用粗箭头和强光效；
- 单张 Frame 移动时长建议为 0.7–0.9 秒；
- 两张 Frame 之间保留 0.15–0.25 秒间隔；
- 设计稿进入浏览器后不要显示为图片直接贴入，而是触发浏览器内部下一阶段的结构构建。

### 4. 浏览器逐步构建

每张 Frame 到达右侧后，浏览器内部依次完成一组视觉变化：

```text
结构区块出现
→ 内容区块出现
→ 图片与文字出现
→ 样式和间距补齐
```

建议使用：

- `opacity` 淡入；
- `transform: translateY()` 上移；
- `clip-path` 局部揭示；
- 轻微的颜色从灰色过渡到蓝色或黑色。

不建议使用：

- 终端代码滚动；
- 复杂数字进度条；
- 反复闪烁的错误提示；
- 大幅度旋转或弹跳。

### 5. 困境文案出现

当右侧浏览器完成一次“从空白到页面”的构建后，底部左右两侧分别出现困境文案：

- 左侧先出现“设计师的困境”；
- 右侧延迟约 120ms 出现“开发人员的困境”；
- 两侧正文以轻字重淡入；
- 两组文案同时停留，不做强调色切换。

### 6. 进入下一页

- 底部 `Codify 插件` 和 `Codex` 标签最后出现；
- 两个标签分别向左右展开为下一页的两条方法路径；
- 当前页的设计稿堆叠和浏览器窗口保持不动；
- 下一页接续展示两种方法生成真实 HTML 的结果对比。

## 实现要求

- 将左侧设计稿堆叠作为独立容器，例如 `.design-stack`；
- 将右侧网页开发过程作为独立容器，例如 `.browser-build`；
- 每张设计稿使用独立元素，例如 `.frame-card[data-frame="01"]`；
- 每个网页构建阶段使用独立状态，例如 `.build-stage[data-stage="structure"]`；
- Frame 移动和网页构建必须由同一组状态控制，避免设计稿已经到达右侧但网页还未更新；
- 动画播放期间禁用翻页重复触发，动画结束后恢复交互；
- 页面需要支持 `prefers-reduced-motion`，降级后直接显示完整的左右构图和最终文案；
- 所有截图和 Logo 使用本地资源，避免现场网络加载失败；
- 使用 `object-fit: contain` 保留 Frame 设计稿比例，不对设计稿进行非等比拉伸；
- 浏览器窗口内部的设计稿或网页内容必须与页面圆点背景分层，避免背景圆点穿透截图内容。
