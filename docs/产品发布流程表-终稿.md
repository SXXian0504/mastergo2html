# 产品发布流程表（Codex Skill 单路径）

> 正式发布约 23 分 30 秒，Q&A 约 5 分钟，总计约 28 分 30 秒，保留约 1 分 30 秒缓冲。

| **篇章** | **小节** | **内容** | **展示** | **时长** | **备注** |
|---|---|---|---|---:|---|
| **开篇** | 困境介绍 | AI 已经能够生成代码，但设计师为了把设计稿转换成页面，仍需要解释页面结构、素材、布局、响应式、交互和多页面关系，逐渐被迫成为“Prompt 工程师”。 | 纯黑背景大字：**“设计师不该为了生成页面，先学会写 Prompt。”**；随后让一句简单需求逐渐膨胀成大段 Prompt。 | 0:50 | 不先介绍产品和个人背景，先让设计师观众产生共鸣。建议 2 页。 |
|  | 现有方法、缺点 | 对比 Codify 插件与 Codex + 官方 MCP 两种方式。Codify 操作直接，但在当前样例中存在蒙版素材丢失、页尾 Logo 变成黑框、布局错位和样式偏差；Codex + 官方 MCP 灵活，但需要长 Prompt、反复补充上下文，结果受指令质量影响，并产生额外 Token 和沟通成本。 | 先用一页展示两条使用路径，再用相同设计稿、相同位置展示两种生成结果；重点放大页尾 Logo 和布局错位区域。 | 1:30 | 不做主观攻击，只呈现相同输入条件下的可观察结果。对照条件写入页脚或 Q&A 备用页。 |
|  | 开发动机 | 与其让每一个用户重新组织提示词、重新告诉 Agent 应该怎样转换和验收，不如把已经验证过的专业方法固化成可复用的 Skill。 | 黑底大字：**“不要让用户记住方法，让 Skill 记住方法。”** | 0:50 | 这里讲产品动机，不讲“因为这是我的实习项目”。 |
| **洞察** | 归纳产品需要解决的问题 | 产品需要同时解决三件事：①设计信息完整进入生成过程；②用户不需要编写和维护长 Prompt；③输出不是孤立代码，而是可运行、可验证、可继续开发的工程。 | 三个关键词依次出现：**完整理解 / 简单使用 / 工程交付**。 | 1:00 | 三项问题应分别对应后面的三项产品优势。 |
|  | 核心洞察 | 高质量设计稿转代码不是“一次模型生成”问题，而是一个包含设计事实、分阶段处理、视觉验证和工程验收的工作流问题。 | 两页递进：**“问题不是模型不会写代码。”** → **“而是正确的方法，没有被固化。”** | 0:50 | 这是从问题进入产品的核心转折，翻页前留出停顿。 |
|  | 解决方法 | 将设计稿转换的方法、步骤和验收规则封装成 Codex Skill：读取设计 → 逐页生成 → 视觉验证 → React 合并 → 工程检查。 | 五阶段横向流程，节点逐个点亮。 | 1:20 | 只展示五个用户能理解的阶段，不展示内部所有脚本和中间 JSON。 |
| **产品登场** | 产品介绍 | 发布产品：一款面向设计师与前端交付场景的 Design-to-React Codex Skill。用户只需说明目标，Skill 自动将 MasterGo 多个页面转换成 React 项目。 | 纯黑背景，产品名使用一次 Mask Reveal；副标题：**A Codex Skill for Design-to-React**。 | 0:50 | 产品与 Skill 展示名统一为 `MasterGo2Code`。全场最明显的 Slide 动效只放这里。 |
|  | 实操展示引入 | 展示用户实际需要输入的唯一指令：“将当前选中的 MasterGo 页面转换成 React 项目。”播放前提醒观众关注两点：用户输入了多少信息，Skill 自动接管了多少步骤。 | 暖白背景，真实指令居中，下方小字：**That’s it.**；随后黑屏章节页：**From frames to a working product.** | 0:30 | 不提前解释视频中的全部步骤，让视频自己建立第一印象。 |
|  | **实操展示** | 剪辑视频完整展示：MasterGo 中选择多个 Frame → Codex 输入一句指令 → Skill 被加载 → 每个页面独立生成 HTML → 逐页截图验证 → 合并为 React/Next.js 项目 → 展示路由跳转 → 响应式结果 → TypeScript、Build 和视觉验证。 | **全屏 16:9 演示视频。**关键阶段使用极短字幕，标注实际原始生成耗时。 | **4:30** | 不现场演示；不长时间播放终端滚动；视频控制在 4 分 30 秒以内。 |
|  | 实操展示总结 | 用户只负责表达最终目标，Skill 负责执行专业过程；多个设计页面最终成为一个可运行、可验证、可继续开发的项目。 | 视频最终画面定格，叠加：**“One instruction. One working project.”** | 0:30 | 不马上解释技术架构，先让最终结果停留 1–2 秒。 |
| **产品优势** | **优势 1：精确度** | 通过设计节点、素材映射、Frame 截图和逐页视觉验证，尽可能保留静态资源、蒙版、文本、颜色、布局关系和主要样式；重点证明 Logo 不再变成黑框、页面布局不再明显错位。 | 设计稿 / Codify 或普通结果 / 产品结果三方对比；再用设计稿和生成结果叠加切换。标题：**“复杂素材，完整保留。”** | 1:40 | 不直接宣称“还原度 >95%”，除非已经定义指标、视口、样本量和计算方法。 |
|  | **优势 2：易用性** | 用户不需要编写大段 Prompt，也不需要每次重新说明设计稿转换步骤；Skill 记住固定方法，并自动执行多页面处理和工程合并。 | 左侧展示被折叠的长 Prompt，右侧只展示一句指令；长 Prompt 收缩成一句话。标题：**“用户只需要说明目标。”** | 1:20 | 易用性重点不是“少点一个按钮”，而是减少 Prompt 组织和工作流管理成本。 |
|  | **优势 3：降本增效** | 减少手动量尺寸、整理素材、编写 Prompt、逐页生成、人工合并路由以及反复修复生成偏差的时间；让前端从可运行首版开始，而不是从空目录开始。 | Before/After 流程对比；可补充已验证样例的生成耗时、人工步骤数或返工次数。 | 1:20 | 只展示已经统计的数据。Token 和费用未统计完成前，不写“每页 3–6 元”等具体结论。 |
| **价值** | 用户价值 | 对设计师：减少解释设计和交付损失；对前端：获得可继续开发的第一版工程；对团队：将个人经验变成可重复的标准工作流。 | 三句价值依次出现，或拆成设计师、前端两张快速页面。 | 1:10 | 面向设计师的发布会，应先讲设计师价值，再讲前端和团队价值。 |
|  | Before / After | Before：长 Prompt、重复补充、素材丢失、逐页人工整理；After：一句目标、固定 Skill、逐页视觉验证、自动形成 React 工程。 | 左右分屏的用户旅程；左侧复杂且灰，右侧简洁并使用产品蓝。 | 1:00 | 这里总结的是整个用户体验，不再重复三个优势的技术细节。 |
| **幕后** | 个人贡献 | 产品及完整链路由个人独立开发，覆盖设计数据采集、素材与蒙版处理、AI 工作流、HTML 生成、视觉验证、Agent Skill、React 工程迁移和工程检查。 | 黑底大字：**“One workflow. Built end-to-end.”**；下方用一条闭环表示完整能力范围。 | 1:10 | 最终实习考核必须保留，但不要做成任务清单或周报。重点讲问题定义、系统设计与落地闭环。 |
| **未来** | 产品边界 | 当前定位是将 MasterGo 网页设计稿转换为可运行、可继续开发的 HTML/React 首版；复杂业务接口、动态数据、特殊动效和完整生产发布仍需要前端开发继续处理。 | 暖白背景大字：**“第一版，不是终点。”**；下方最多三行边界。 | 1:10 | Android、App 不属于“产品边界”，应放到下一步计划。主动说清边界会提升可信度。 |
|  | 下一步计划 | 拓宽到 App/Android 等设计稿场景；增强复杂交互与响应式；接入团队组件库和工程规范；建立标准测试集、Token/成本指标和自动视觉修正闭环。 | 由当前 Web/React 延伸到未来场景的简洁路线；最多突出三个方向。 | 1:00 | 主讲只说三个优先级最高的方向，完整 Roadmap 放 Q&A 备用页。 |
| **结尾** | 产品 Slogan | 回扣开场：产品不是另一个需要设计师维护的大 Prompt，而是让 Skill 记住设计稿转代码的专业方法。推荐 Slogan：**“一句话，从设计稿到 React 项目。”** | 纯黑背景，产品名与 Slogan 居中；画面停留 2 秒。 | 0:50 | 备选：①让 Skill 记住方法，让设计师专注设计；②从设计稿，到可运行项目。 |
|  | 感谢到场 | 口头感谢 Mentor、评委与参与项目的人。 | 不单独制作“Thank You”页，继续停留在产品名和 Slogan 页面。 | 0:10 | 最后一帧应该让观众记住产品，而不是只记住“谢谢”。 |
| **Q&A** | 评审问答 | 回答产品原理、视觉指标、耗时与成本、失败场景、工程质量、个人贡献和后续规划。 | 根据问题切换到架构、三方对比、数据、边界等备用页。 | 5:00 | 正式内容约 23:30，总时长约 28:30，剩余约 1:30 作为缓冲。 |

## 主流程一句话

> 现有方法仍让设计师承担大量解释与修正工作，因此将设计稿转代码的专业方法固化成 Codex Skill，让用户只需要一句指令，就能把多个 MasterGo 页面转换为可运行、可验证、可继续开发的 React 项目。
